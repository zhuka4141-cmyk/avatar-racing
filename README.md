# 头像赛车（avatar-racing）

浏览器单页自动观赏赛车游戏。按 `2026-09-22-avatar-racing-design.md` 规格实现，并包含后续提出的四项改动（更弯的赛道、更多超车、结算后继续跑、名次可下滑），以及 2026-09-23 的第五批改动（赛道加宽到 14 个车位、随机变道与变道超车、前五名之外随机加速并在超过后自动调速）。

## 在线试玩

- GitHub Pages：https://zhuka4141-cmyk.github.io/avatar-racing/
- 源码仓库：https://github.com/zhuka4141-cmyk/avatar-racing

## 运行

- 直接双击 `avatar-racing/index.html`（file:// 打开即可，页面不发起任何网络请求）。
- 或用任意静态服务器：`python -m http.server 8080`，访问 `http://localhost:8080/avatar-racing/`。
- 头像只在当前页面会话的 Canvas 缓存中存在，不会上传。

## 关键实现

### 状态机

```
setup -> countdown(3.9s，显示 3/2/1/开始) -> racing
racing  --第一名冲线--> waiting（记录 leaderFinishAt，镜头目标切到终点线）
waiting --finishers >= min(10, 参赛人数)--> ending
waiting --waitingElapsed >= 5s---------> ending（按当前进度记录名次）
ending  --全部车辆离开视野 或 12s------> results
results --再来一局--> countdown（保留参赛者资料，重建赛道/种子/随机参数）
```

- `ending`：**不冻结画面**。车辆继续行驶，冲线车辆以 55% 巡航速度沿终点直线段驶出画面；HUD 显示「比赛结束 · 车辆正在驶离赛道」，并提供「查看成绩」按钮可提前查看。
- `results`：结果面板弹出，**动画仍在继续**（车辆继续移动、镜头锁定不动）；名次以 `ending` 开始瞬间的快照为准，不再变化。

### 设置页

- 「添加参赛者 / 填入示例参赛者 / 随机排序 / 清空全部」+ 标题旁徽标实时显示「共 N 位参赛者」；随机排序同时打乱名单与发车格签位（两次独立随机）。
- **导入 CSV 名单**：点按钮选文件，按表头认列（`Fullname` 优先、空白则用 `Username`；头像取 `Avatar URL`），一次把名单换成「头像 + 名字」。
  CSV 解析自己实现，支持引号包裹、字段内逗号/换行、`""` 转义与 BOM（Excel/Google 导出都吃得下）。
  头像按**三级来源**依次尝试：① 仓库自带的 `avatars/<用户名>.jpg`（同源、不会过期、不受扩展拦截）→ ② CSV 里的 `Avatar URL`（`referrerPolicy = no-referrer`，实测 Instagram CDN 不防盗链但**没有 CORS 头**）→ ③ 彩色首字母默认头像。
  因为远程图没有 CORS 头，**赛车头像用 canvas 圆盘绘制**（跨域污染只影响像素读取，不影响 `drawImage`），**卡片缩略图直接用图片地址**（污染的画布不能 `toDataURL`）；
  单张图三级全失败也只影响那一行。

### 赛道生成（阶梯布局 + 真 U 型弯）

- `mulberry32(seed)` 可复现 PRNG；每局新种子，布局为「长直道 → 半圆 U 型弯 → 长直道 → …」的阶梯结构，实测每局 2 个 U 型弯（弯道弧长约占全长 47%）。
- **直道（含缓弯）**：横向摆幅按 `legLen²/(105×半宽)` 限制（约 20–124 世界单位），保证实测曲率半径不低于 1.35 倍半宽 —— 用「航向偏移 = atan(dy/ds)」显式驱动，而不是对曲率积分（后者会累积漂移）。两端套 `sin²` 包络，保证进出直道时航向与基准一致。
- **U 型弯**：半径 = 相邻直道间距的一半（628–728），弧长 πR，转角恰好 180°；转向符号逐次交替，每过一个弯整体沿垂直方向前进一个间距、航向翻转 180°，因此各层直道互不重叠。
- 生成后两项数值自检：最小转弯半径（> 1.35 倍赛道半宽）与自相交（任意弧长相差 1200 以上的两点距离必须 > 赛道宽 + 30）；不通过则换种子重滚，最多 6 次。实测 600 个种子 0 次退化成直线赛道，层间距约 1300–1520 单位（赛道宽 828）。
- 实测 minR 559–717，两个 U 型弯合计占弧长约 47%，弯道密度远高于早期「控制点 + 随机振幅」版本。
- 赛道半宽 414 世界单位（14 个车位并排：车位中心间距 60、车身宽 46）、弧长 9000；起终点各接直线缓冲区（起跑区长度随人数伸缩，冲线后 1400 单位停车区），赛道两端支持线性外推，车辆可一直驶出视野。
- 路缘红白交替**按世界弧长 k×34 分段的四边形贴片**绘制，不再使用 `setLineDash`（其相位从「当前可见段起点」起算，而该起点每帧随镜头移动，会让白条沿赛道一直爬动）；起终点黑白方格线；路面中灰 `#8d9298`，背景浅灰 `#e9edf1` + 淡点阵纹理。

### 速度、超车与防重叠

- 静态差距**拉开**（`baseSpeed ±13%`、`accel ±22%`、`startDelay ≤ 0.5s`）：最快车是最慢车的 1.27 倍，车队会真的拉开、再被落后补偿追回来，而不是全程挤成一团。
- 动态节奏：每车 `pace = 1 + 12%·sin(0.37t+φ₁) + 7%·sin(0.93t+φ₂) + 5%·sin(0.21t+φ₃)`，周期性发力/疲软，名次持续交换。
- 尾流只在**斜后方**（横向 26–62 单位）有效：跟车者 +9%；正后方改为 −3% 乱流，逼出「拉开 → 抽头 → 超越」的动作，而不是一直黏在前车尾后。
- **车辆之间不碰撞**：不做跟车限速、也不互相推开，快车直接从慢车身上穿过去（单测断言：还跟在后面时绝不因为前车掉速）。唯一约束是重叠面积 —— 两车重叠不得超过车身面积的 50%（`MAX_OVERLAP`），超了才横向让位；让位量由「重叠面积 ≤ 50%」反推：完全纵向对齐时横向至少要开 23 单位，纵向错开 39 单位以上就不再限制。
- 主动超车：每 0.25 秒观察前方 220 单位，遇到前车时检查左右空隙及其他车辆的换道目标，向空侧平滑移动；目标保持 1.8 秒，避免尚未完成超车就被拉回原车道。此外每 0.25 秒还有一次「随机变道」判定：没人挡路时也可能换个车道巡航（冷却 1.2–3.2 秒，新车道成为它的巡航车道），并入只看身边 ±50 单位，所以密集车群也换得动道。变道前还要检查「横穿走廊」（当前车道到目标车道之间 ±半个车身宽）里有没有车，避免从别人车身上刮过去而必然造成重叠。**没有车辆数上限** —— 变道与超车在任何车数下都照常发生；逐对处理改成按 s 排序的滑动窗口（只比纵向 230 单位内的邻居），所以车多也不会退化成 O(n²) 全对扫描。
- 重叠兜底每帧跑两遍：`interact` 里逐帧柔性让位（看起来像自然避让），车辆位置推进之后**再强制对齐一次**（一帧内必须达标），因为横向并入的阻尼可能又把两车拉近。按 s 排序后只比纵向 78 单位内的邻居。完整页面（物理 + 渲染）实测每帧：15 车 0.34ms、121 车 1.3ms、300 车 2.7ms，都在 16.7ms 预算内。
- **快速超过**：一旦确实在逼近前车（同车道、130 单位内、速度快 2% 以上），后车就持续获得 +20% 推力直到穿过；同车道超车（落后 90 → 领先 90）实测中位 1.33 秒、最慢 4.8 秒。
- **变道走匀速（线性）**：横向位移按固定速度 `LANE_SPEED = 62` 单位/秒 推进，到位即停。原来用指数阻尼（超车时 λ=3.2、回位 1.4），起步瞬间横向速度会冲到约 190 单位/秒、车头先甩 21°，再慢慢蹭进车位；现在实测变道中横向速度 p95 = 62 单位/秒（正好等于设定值，说明确实是线性）、车身偏航 p95 8.0°、最大 11.6°。
- **越靠后越快（追赶机制）**：按「落后领先者多少」连续给油 —— `clamp(gap/900)×0.45`，落后 900 单位吃满 +45%；领先者本身不加成，所以速度系数最高的永远是最后面那些车（实测前三名 ×1.03、第 13 名以后 ×1.27，此时落后约 478 单位）。用**距离**而不是名次，是因为按名次会出现「刚超到第一就瞬间掉速」的乒乓（两车局实测来回换位 11–24 次）；距离制下每个人的加减速都是连续的。整体系数上限从 1.32 放宽到 1.9，否则后段系数会被截断、随机加速失效。
- **前五名之外随机加速**：第 6 名及以后每 1.2–4.8 秒（70% 概率）触发一次 1.0–3.6 秒的随机加速（+5%~14%），前五名不额外给加速度；快贴上前车（同车道 90 单位内）时加速按距离线性收油。
- **超过后自动调速**：名次上升即进入 1.2 秒调速窗口，随机加速按窗口线性淡出，之后回到自身巡航速度 —— 超过之后不会一路狂飙，但也**不会**因为前面有车就刹车（车辆之间不碰撞）。
- 整体追赶系数上限 1.32，并以阻尼平滑变化，不按名次突然切断，也不直接修改车辆里程。
- 基准速度标定为 `raceLen/21.5`（距离制追赶会让整体节奏偏快，同步放慢重新定标），实测第一名 18.7–20.7 秒冲线（10 局均值 19.8s）。
- **终点前 1800 单位淡出追赶机制**，让中后段保留超车机会，终点附近逐渐由自身速度和每车 ±1.5% 微偏置决定名次。冲线时刻继续用**亚帧插值**反推（`t - dt·(超出距离/本帧位移)`）。
- 时间一律显示到毫秒（`19.110s`）。
- 起步：每排最多 14 车（车位居中排布、中心间距 60）、排距 100 世界单位。起始位置与巡航车道一致，人数增加时延长起跑区，不压缩车距；排距 100 > 车长 78，所以起跑排本身就互不重叠。
- 车身全部白色（前翼、鼻锥、侧箱、尾翼、四轮、驾驶舱环），仅用浅灰描边与阴影保持可读；驾驶舱位置显示圆形头像（预乘好黑圈与圆形的贴图），缺图时用彩色首字母圆标。
- **不做任何简化渲染**：车身与阴影预渲染成贴图、头像预乘成圆盘贴图、每车一次 `setTransform` + 1–2 次 `drawImage`，因此 120 辆车也全部是完整车形 + 完整头像（实测 120 车 ≈ 59fps）。
- 车体在世界坐标绘制（变换含 y 翻转），头像与姓名标签在屏幕空间绘制以避免文字镜像。**画面上每台车都一直显示名字**：不再按「离镜头中心距离」筛选、也没有数量上限（旧实现是 34% 半径内最多 6 个）。**名字不做任何让位/避让** —— 位置固定在车头正上方（只做「不出画面」的边界收拢），重叠时就让它重叠：标签底色 `rgba(26,33,44,0.5)`、文字 `rgba(255,255,255,0.92)`，叠在一起也能看见下面那层；只有驶出画面才淡出（6/s）。标签宽度按名字缓存，120 车时不必每帧 `measureText`，每帧 O(n²) 的同名统计与重叠检测都已去掉；绘制顺序固定按参赛者 id，纯粹让重叠时的覆盖顺序稳定。

### 镜头

- `racing`：目标 = 当前第一名进度，`focusY = 0.62`；相机朝向取「当前位置 → 前方 330 单位」的方向，弯道中也能把前方赛道与左右边界保持在画面内。
  （曾实现过「按车队包围盒自动退远 + 对准车队中点」的取景，可见车数从 77% 提到 100%，但车会明显变小，按需求已改回固定缩放盯第一名。）
- `ending / results`：目标切换为终点线（`raceLen - 40`），平滑移动后锁定，车辆从镜头前驶过并离开画面。

### 名次面板

排行：已冲线按 `finishTime` 升序 → 未冲线按里程降序 → id 稳定破平局。结算瞬间生成快照，面板列出**全部**参赛者：前 5 名直接可见（前三名有金银铜配色），第 6 名起在分隔线下方，列表区域可上下滑动。

## 本次起步与超车修复验证（2026-09-23）

无需安装依赖即可运行物理回归：`node qa_physics.js`。14 项检查覆盖 2/8/15/120/121/300 车起跑间距与首秒前进、并排不刹车、主动超车、车身穿过（重叠 ≤ 50%、后车不为前车掉速）、后车追赶、前五名外的随机加速、超过后的自动调速、整场比赛及结算。

浏览器回归：设置 `PW_PATH` 为现有 `playwright-core` 路径，运行 `node qa_start.js [截图目录]`。脚本使用本文件所在目录的网页，无硬编码项目路径；覆盖手机 15 车、桌面 8 车、手机 120 车前 8 秒、12 车慢车超时、终点镜头、成绩列表和重开。此次均通过，页面错误数为 0。超过 120 车仅验证了起跑模拟，未声称浏览器全程性能保证。
